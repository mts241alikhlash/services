Questions now belong to one package. A teacher creates an empty package, then writes questions in it, imports an Excel or Word file into it, or copies questions from an approved or scheduled package of the same subject and grade; a copy keeps where it came from and changing it never touches the original. A package goes DRAFT, SUBMITTED, APPROVED (or RETURNED with a note and notes on single questions) and only an approved package, or one already scheduled for another classroom, can be scheduled. Submitting, approving and returning are whole-package actions with a review history; an approver cannot approve a package they wrote unless they manage all questions. The package view marks each question as new, changed or copied. A teacher lists their own packages in every status and the approved or scheduled packages of others; drafts of others stay hidden. Copying a package now copies its questions. GET /exam-packages/candidates is gone and the import takes a packageId instead of a subject and a grade. Roles that build exams need exam-packages.read, create, update and delete; reviewers need exam-questions.approve. A package can be changed, submitted, imported into or deleted only by the teacher who started it or by someone who manages all questions. The migration refuses to run while questions exist, so reset the exam database first.
